# 設計說明

這份文件記錄每個設計決定**是什麼**和**為什麼**。之後要改行為前，請先看這裡，並在這裡更新理由。

## 目標與範圍

- **主要目標**：在 iPhone 上用三角編號打字。執行環境是倉輸入法（Hamster）裡的 RIME 引擎。
- **次要目標**：同一份方案也能用在其他 RIME 前端，例如 Mac 的鼠鬚管、Windows 的小狼毫，但不針對實體鍵盤做最佳化（見文末「實體鍵盤的限制」）。
- **不做**：自己的 App，也不上架 App Store。透過倉輸入法就能在 iPhone 上使用，不需要 Apple 開發者帳號（每年 US$99），也不用維護一個 App。

## 架構

```
data/3corner.cin ──build.py──▶ rime/sanjiao.dict.yaml ─┐
                                                        ├─▶ RIME 引擎（倉輸入法裡）
rime/sanjiao.schema.yaml（手寫的規則）─────────────────┘
tools/keyboard.py ──build.py──▶ hamster.custom.yaml ──────▶ 倉輸入法的鍵盤畫面
```

- **規則**和**資料**分開：碼表由程式產生，規則用手寫。之後更新碼表不會動到規則。
- 碼表**原封不動**收進 repo，並用 SHA-256 鎖住版本，確保每次建置用的都是同一份資料。

## 輸入行為

| 情境 | 行為 | 理由 |
|---|---|---|
| 打數字 | 一律當作編碼 | 見下方「為什麼數字不能選字」 |
| 打字途中 | 即時顯示候選，「~」後面是還沒打的碼 | 觸控螢幕看得到候選，不必打滿 6 碼 |
| 結尾的 0 | 可以省略：`101` = `101000` | 照 Windows 版 PIME 三角輸入法的「Enter 補 0」規則，少按幾下 |
| 選字 | 點候選字，或按空白鍵選第一個 | 手機輸入法的慣例 |
| 打滿 6 碼後繼續打數字 | 先送出第一個候選，再開始下一個字 | 常用字不必按空白鍵就能連打 |
| 編碼查不到字時按空白鍵 | 不做任何事，保留編碼 | 避免把一串數字當成文字送出；用刪除鍵修正 |
| 換行（Enter） | 送出原本打的數字 | 讓中文模式下也能直接輸入數字 |
| 打碼途中按標點 | 先送出第一個候選，再接上標點 | 「三，」可以一口氣打完 |
| 候選順序 | 固定，不學習 | 見下方「為什麼固定字序」 |

### 為什麼數字不能選字

電腦版三角輸入法打滿 6 碼後，按數字是選第幾個字。但 RIME 引擎在處理按鍵時，會先把數字交給「拼寫」處理（`speller`），選字（`selector`）排在後面。所以同一個數字鍵沒辦法依照「打了幾碼」切換用途。

要做到這件事，必須寫 Lua 外掛，但倉輸入法開源版的 Lua 模組是關閉的，目前的 App Store 版本也無法確認是否支援。所以這個方案只用純 YAML 設定，換取最大的相容性。在觸控螢幕上，直接點候選字本來就比按數字直覺。

### 為什麼固定字序

RIME 可以記住常選的字並排到前面（`enable_user_dict`）。實測發現，只要選過一次第 4 個字，它下次就會排到第 1 位。這時候按空白鍵或連打，送出的就不是平常那個字了。

三角編號的使用者習慣記住字的位置，所以預設固定順序。想開啟學習的人可以加一個設定檔，見 `customize.md`。

## 候選排序

約 12% 的編碼對應不只一個字。排序規則：

1. **常用程度分四層**：Big5 常用字 → Big5 次常用字 → 其他基本區的字和符號 → Unicode 擴充 B 區以後的罕用字
2. **同一層內**維持原碼表的順序

原碼表有 1,027 個編碼是罕用字排在常用字前面，例如 `018660` 的「䯧」排在「高」前面。照上面的規則調整後，常用字都排在第一位。罕用字放最後還有一個原因：有些字型顯示不出擴充 B 區的字。

實作在 `tools/ranking.py`。RIME 依照碼表第三欄的權重排序，數字越大越前面。

## 標點

鍵盤送出 ASCII 符號，再由方案裡的 `punctuator` 轉成全形標點，例如 `,` → `，`、`\` → `、`、`[` → `「`。每個符號只對應一個標點，按下就直接輸入，不跳出選單。上滑、下滑要在長按判定時間內滑完，倉輸入法才會當成滑動；滑太慢會被當成拖曳，放開後不輸入。標點會經過 RIME 處理，所以打碼途中按標點，會先送出目前的字。

## 鍵盤（倉輸入法）

```
符號   1   2   3   ⌫        ⌫ 上滑：清除正在打的編碼
ABC    4   5   6   ，       ， 上滑：；
🌐     7   8   9   。       。 上滑：：
？     、  0   空格 換行     ？ 上滑：！   、 上滑：「  下滑：」
```

- 數字照手機撥號盤排列，0 在 8 的正下方。
- 🌐 一定要有：有 Home 鍵的 iPhone（例如 iPhone SE）在鍵盤下方沒有系統的地球鍵。
- 「符號」和「ABC」切換到倉輸入法內建的符號與英文鍵盤，在那裡可以按返回鍵回到三角鍵盤（`isPrimary: true`）。

### 鍵盤語法

鍵盤用官方 wiki「自定义布局」的語法（2.2.0 以後），例如 `action: { character: { char: "1" } }`。最後一個開源版本（2.1.x）用的是另一種寫法 `action: character(1)`，曾經兩種都產生；2026-10-16 實機確認 App Store 版本用 wiki 語法後，就只保留這一種。

## 安裝包

| 檔案 | 內容 | 給誰 |
|---|---|---|
| `rime-sanjiao-hamster.zip` | 方案、碼表、`default.custom.yaml`、`hamster.custom.yaml` | 倉輸入法使用者，一次匯入就好 |
| `rime-sanjiao-schema-only.zip` | 方案、碼表 | 自己管理 RIME 設定的人（任何 RIME 前端） |

- 檔名**不含版本號**，讓 `releases/latest/download/<檔名>` 成為固定的最新版連結，使用者存一個書籤就能更新。版本號記在方案的 `schema/version` 和發布標籤上。
- zip 裡**沒有資料夾**，這是倉輸入法匯入的要求。
- 同樣的原始檔，每次會產生完全相同的 zip（時間戳記固定），方便比對版本。
- `default.custom.yaml` 用 `schema_list/@before 0` 把方案**插到清單最前面**，不會蓋掉清單上原本的方案。一定要排第一：倉輸入法每次叫出鍵盤都載入清單上第一個方案，排在後面的話數字會被別的方案直接送出（實機測到的問題）。但這個檔案本身會取代使用者原有的 `default.custom.yaml`，所以已經有自訂設定的人應該用 schema-only 包。

## 實體鍵盤的限制

在鼠鬚管、小狼毫上使用時，數字一樣只會打編碼，候選旁邊的「1. 2. 3.」標號按了沒有作用。選字方式是：空白鍵選第一個、方向鍵移動再按空白鍵，或用滑鼠點。`-`、`=` 可以翻頁。如果之後有需求，可以另外做一個給實體鍵盤用的方案，但會需要 Lua。
